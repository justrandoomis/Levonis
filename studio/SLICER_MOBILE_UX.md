# Mobile UX

LEVO presents the same editor state on desktop and mobile instead of maintaining a simplified second slicer. Below 900 px the editor is laid out as the owner's reference screen (IMG_8466): one scrolling column of clay cards around the same engine the desktop uses.

## The phone column (plan item C6)

Top to bottom, as the reference draws it:

1. **Top bar.** A back chevron to the LEVONIS community, «LEVO Studio» over «تجهيز ملفات الطباعة», then «حفظ» and, at the end edge, «استيراد» (gold outline), in the order of the reference. Save writes to the account when signed in (creating the account project the first time) and to a draft on this device otherwise, and says which. Leaving during a slice, or with account changes not yet saved, asks first.
2. **«المزيد» and the mode.** The overflow entry sits on the start side; the Simple / Advanced switch («مبسط» / «متقدم») on the end side, a radiogroup the arrow keys walk in the writing direction. A key the switch handles goes no further: it never also reaches the engine, whose arrow keys nudge the selected model.
3. **Viewport card.** About 46% of the screen tall, with an overlay toolbar along its top edge: expand (an in-app full-height view, since iPhone has no Fullscreen API), «إعادة العرض», the bed view, and the file name in LTR. The canvas stays the engine's dark island in both themes. One finger orbits inside the card, over the stats card and the bed warning too; the page scrolls from anywhere outside it.
4. **Transform tiles.** Move, Rotate, Size, Arrange. The pressed tile is read from the engine's own gizmo rail, never guessed. The toolbar is one tab stop: the arrow keys, Home and End move the focus across the four tiles in the writing direction and go no further, so they never nudge the model.
5. **Print settings.** Printer (opens the printer grid), material, layer height, infill, supports, and «كل الإعدادات» in Advanced. The rows list only what is real: materials whose engine preset ships for the printer (PLA Basic, and PETG Basic where the engine has it), the Quality and Strength tiers, and the value the kernel will actually use, marked «(مخصص)» when a hand edit moved it off every tier. The material row reads the filament on T1: an imported project that brings PETG Basic reads «PETG Basic» (and the sheet header «PETG»), any other filament reads as its own short name with «(مخصص)», and picking the material the selector already holds takes T1 back to it. A 3MF whose settings hold only process keys leaves T1 with no named filament (the kernel then slices with its own defaults: PLA at 200 °C), so the row reads «PLA (مخصص)» / "PLA (custom)" / «PLA (تایبەت)», never «PLA Basic»; only before the first preset load does the row show the selector. Only a change a person makes in the engine panels counts as a hand edit; the engine writing settings back after a preset load does not, so the notice about kept or replaced edits speaks only of real ones.
6. **Model size and orientation.** The size is measured from the model's own vertices after scale and rotation. The three orientation chips (as imported, automatic, on its side) turn the selected object, or every object when none is selected, with an undo; the pressed chip is read from the current rotation. The arrow keys move the focus between the chips (turning stays a press) and go no further.
7. **Readiness banner.** Driven by the real preflight and the slice result: hidden while there is nothing to judge, then blocked (danger), outdated (warning), generic fallback presets (warning), sliced (success) or «جاهز للتقطيع» (success). It never shows success over a blocker. A model outside the bed of its plate, wholly or in part, is blocked before the slice the engine would refuse; the title is «أكبر من حجم الطابعة» only when a model is too big, and «خارج حدود سطح الطباعة» when the models only sit in the wrong place. The engine's over-bed rejection of a slice holds only for the scene and settings it judged: once a model moves (for example after «ترتيب») or a setting changes, the placement check decides again. The slice acts on the current plate only, so when that plate has no visible model while another plate does (after «+ Plate»), the banner is a warning, «Plate الحالية فارغة», never «جاهز للتقطيع».
8. **«تقطيع المجسم».** The one gold primary. It shows progress with cancel while slicing (and the retry rung), «أعد التقطيع» when the result is outdated, and «الطباعة والتصدير» once the result is fresh.
9. **«تصدير الملف».** 3MF always; G-code only from a fresh result, otherwise «متاح بعد التقطيع» or «أعد التقطيع أولًا». The Export G-code link of the engine, reachable through «كل الإعدادات», follows the same rule and is not shown over an outdated result. «المزيد من خيارات التصدير» opens the print sheet once there is a result. The engine's arrow keys listen on the whole window, so an arrow pressed on any shell control («المزيد», the G-code tile itself) can move the selected model: the keyup of every key marks a candidate edit, the result goes outdated at once, and pressing the tile reads the scene again, so a key still held down cannot hand out the old G-code either.

## Nothing is dropped

The reference leaves out most of the editor. Everything the old five-action bar and tool tray reached is in the overflow sheet («المزيد»), grouped in the order a print is made: files (add, projects, new project); object tools (duplicate, split, place on bed, support paint, cut, auto-orient, delete; duplicate, split and delete wait for a selected object); the plate (add a plate, slice all, delete all); the view (prepare / preview, zoom all, zoom bed, undo, redo); output (MakerWorld 3MF, share G-code, every plate, print and export); settings (the Setup sheet, all settings); account and printer (sign in or out, connect a printer); language; appearance; and the platform status with the source-code link. That link (AGPL-3.0-or-later) is two taps from the main screen: «المزيد», then «المصدر وإشعارات المكتبات».

## Desktop workflow

At 900 px and wider, LEVO keeps the native full workspace: top project actions, prepare/preview tabs, gizmos, object tools, right sidebar, plate tabs, slice current/all, and G-code export. The LEVO header adds explicit Files and Print & Export entry points. It is re-tinted with the same tokens and is otherwise unchanged. The phone column and the desktop are one DOM tree told apart by the stylesheet, so a tablet turning across 900 px keeps its scene.

## Visual system

- Two themes, chosen per device (system, light or dark) in the overflow sheet or in Settings. Dark is the reference's blue charcoal; light is the site's cream. The browser chrome colour follows the theme.
- Clay grammar (site row 207): one light from above, a lit top rim, a shaded base and a soft cast. Cards, tiles and controls are raised; the transform tray is an inset well.
- Sand-gold clay marks the one primary («تقطيع المجسم», owner override D-2) and the current mode, transform tool, orientation, language and appearance (owner override D-3), each with aria-checked or aria-pressed and a heavier label as the non-colour cue; the chosen language and appearance also carry a check mark, as do the chosen editor mode and Quality, Strength and infill tiers in Settings and the chosen connection method (its check mark takes the place of its icon). The Projects sheet's chosen tab is ink on the sand (10:1 in dark, 5.9:1 in light), never white. In light, every sand fill carries a 1 px edge so it keeps a 3:1 boundary on cream.
- Cairo is self-hosted (arabic and latin subsets plus the six-letter Sorani patch), because the CSP is `font-src 'self'` and documents are cross-origin isolated.

## Accessibility and resilience

- Every control is at least 44 px tall, the Settings switch (its 52 x 30 track inside a 44 px target) and the About sheet's legal summary and source link included; text is at least 11 px (the reference draws captions near 9 pt).
- Buttons have visible labels or accessible names and keyboard focus indicators; the focus ring is its own token in each theme.
- Modal sheets use dialog semantics, close by the handle (drag or keys), the backdrop or Escape, and take focus when they open. While a sheet is open the page behind it is inert and Tab wraps inside it; closing it by any path gives focus back to the control that opened it. Escape also returns from the expanded viewport and gives focus back to the expand button. While the viewport is expanded, the column under it is inert, so Tab never lands on a control nobody can see. While a sheet is open no key reaches the engine behind it (its arrows, Delete and letter shortcuts edit the scene), and the language and appearance groups in the sheet are walked with the arrow keys, Home and End; the appearance follows the focus, the language waits for Space or Enter because it turns the whole interface. In the sheets, the printer grid, the editor mode and the Quality, Strength and infill tiers are radiogroups with one tab stop, walked by the arrows, Home and End (the printer only drafts until «تطبيق»), and the connection methods are tabs, each controlling the tabpanel below them, as are the two rows of tabs in the Projects sheet (a named tablist, one tab stop, 44 px tall). The viewport card's own toolbar (expand, «إعادة العرض», the bed view) is one tab stop walked by the arrows, so an arrow on it never nudges the model. The Support switch is named by its label.
- Controls drawn on the dark canvas take the canvas focus ring in both themes; the light theme ring is made for cream cards.
- The readiness banner is a polite status, or an alert when it reports a blocker. Error and notice rows use alert and status roles.
- The engine reports in English. Every sentence it can send to the message row (the project import summary, «select an object first», economy mode, an empty plate, export results and the rest) is mapped to the Studio dictionary in Arabic, English and Sorani (`app/engine-messages.ts`); a sentence the map does not know reads as a generic line in Arabic and Sorani, never as raw English. The shell's own counts agree with their numbers in each language («مجسم واحد», «3 مجسمات», «تم القص إلى قطعتين», "1 model exceeds", «کرا» and «کران»), the cut and the ZIP notices included, the Quality and Strength tiers and their wall counts are named in each language, and a preset that takes back a setting the person changed says how many, never the engine's key for it.
- An undo offer in the message row («تراجع عن القص», the arrangement, the orientation) stands only over the objects it was raised over: a delete, «حذف الكل», a duplicate or an import takes it down, and an undo pressed over other objects says it is unavailable and changes nothing.
- A key that changes nothing (a Tab, including the Tabs through the engine canvas) never marks a synced account project unsaved, so the badge stays «متزامن», the back chevron asks nothing, and a version made current from the keyboard reloads the editor as it does with the mouse. A key that moves the model still makes the slice result stale.
- Reduced-motion preferences disable nonessential animation.
- Picker and drag/drop use the same format normalization, ZIP analysis, progress, and size limits.

## Known UX gaps

The engine's own panels (reached through «كل الإعدادات» in Advanced) still carry its English labels; the message row does not. The engine's own canvas does not follow the light theme (its clear colour is fixed in the vendored build), so the viewport stays dark in both themes. Unsupported geometry tools stay visible but disabled in the native object toolbar in Advanced mode so their status is discoverable rather than hidden.
